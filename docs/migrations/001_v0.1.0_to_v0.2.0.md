# Migration: Skelantic v0.1.0 to v0.2.0

## Context
Skelantic v0.2.0 introduces a fundamental architectural shift. The engine no longer relies on the untyped `LinterContext` (`ctx`) and arbitrary keyword arguments (`kwargs`) for processor functions. Instead, it generates a strict, type-safe "File System ORM" called `RepoGraph`. 

## Refactoring Instructions for AI Agents
When refactoring a repository to comply with Skelantic v0.2.0, you must strictly follow these rules:

1. **Delete the old generated Pydantic models:**
   The old Skelantic generator created multiple `.py` files inside a dedicated folder (often `tools/skelantic/models/`). You MUST delete this entire folder and all its contents to prevent Pyright and Python from throwing duplicate import or undefined variable errors. Skelantic now generates a single `types.py` file.

2. **Remove `ctx: LinterContext`:**
   Processors must not accept `ctx: LinterContext`. Do not use `ctx.extracted_data`.

3. **Use the `RepoGraph` for matching and data access:**
   - Import the local `RepoGraph` (usually from `tools.skelantic_types` or similar).
   - Change the type hint of the `node` parameter from `FileNode` or `DirectoryNode` to the specific generated class (e.g., `node: RepoGraph.Docs.Sales.SlugMd`).
   - The `@processor` decorator's `match=` parameter is now mostly obsolete and should be removed if the type hint uniquely identifies the target.
   - Access template data strictly via `node.data` (which is now a validated Pydantic model), NOT via dictionaries.

4. **Access Path Variables via `path_params`:**
   - Remove dynamically injected kwargs (like `slug: str`) from the processor's signature.
   - Access them strictly via `node.path_params` (e.g., `issue_slug = node.path_params.slug`).

5. **Dependency Inject Global State:**
   - If a processor needs to aggregate data globally (previously done via `ctx.store`), define a custom Pydantic `BaseModel` (e.g., `class MyState(BaseModel): ...`).
   - Add this state class to the processor's signature. Skelantic will automatically instantiate it as a singleton and inject it.

6. **Refactor `config.yaml` files (Strict Validation):**
   - **No Deep Paths:** Keys in `directories` and `files` can no longer contain slashes (`/`). You must convert `"backend/src"` into nested `directories: backend: directories: src:`.
   - **No Wildcards:** Keys can no longer contain `*` or `**`. Replace them with strictly typed variables like `"{name:char(1,)}.md"` or `"{slug:char(1,)}.yaml"`. The old `{slug}` fallback and the `words` type have been removed! Use `char(min,max)` or `digit(min,max)`.
   - **No `authorize`:** The `authorize` field has been removed. If a file should exist but not be parsed, just define it. If a file should be ignored completely by the linter, use `ignore: true` on the node.

7. **Refactor Skeletal Templates (`.md` files):**
   - The type `any` has been removed. Use `str` or `text` depending on your use case.
   - The type `slug` has been removed. Use `kebab-case` or `snake_case` instead.
   - The type `int` now strictly forbids leading zeros (e.g., `0042` is invalid, but `0` or `42` are valid). If you need leading zeros, use the new `digit` type (e.g., `digit(1,)`).
   - The type `decimal` now requires a mandatory dot and forbids leading zeros before the dot (e.g. `0.42` or `4.2` are valid, `00.5` or `4` are invalid).

8. **Update AI Skills:**
   Run `skelantic migrate` once to update the local AI skill definitions in `.gemini/skills/skelantic/`. This ensures your agent is aware of all the new rules and commands.

### Example Transformation

**Before (v0.1.x):**
```python
from skelantic.commons.nodes import FileNode
from skelantic.commons.context import LinterContext
from skelantic.commons.decorators import processor

@processor(match="docs/issues/{slug}.md", phase=2)
def validate_issue(node: FileNode, ctx: LinterContext, slug: str):
    data = ctx.extracted_data.get(node.rel_path.as_posix(), {})
    if data.get("status") == "DONE":
        # ...
```

**After (v0.2.0):**
```python
from skelantic.commons.decorators import processor
from tools.skelantic_types import RepoGraph # Import the generated types

@processor(phase=2)
def validate_issue(node: RepoGraph.Docs.Issues.SlugMd):
    # Data is automatically validated Pydantic model
    model = node.data 
    # Path variables are automatically extracted
    issue_slug = node.path_params.slug 
    
    if model and model.status == "DONE":
        # ...
```
